# FAQ: кондиционер Haier в Home Assistant — полное локальное подключение

Гайд для владельцев кондиционеров Haier из «европейского» семейства
(приложение **Haier U+ / uHome / Good Air**), которые хотят управлять ими из
Home Assistant **полностью локально** — без облака и без паяльника.

Всё описанное проверено на реальном **AAC1UKZ01** (семейство прошивки
*compact-12*). В открытом доступе информации по подключению именно таких
кондиционеров не было — этот документ закрывает пробел.

## 1. Подойдёт ли мне это?

Ваш кандидат — «наш», если:

- в приложении кондиционер добавляется через **Haier U+ / uHome / Good Air**
  (`com.haier.uhome.haiergoodairabroad`) — НЕ hOn, НЕ Haier Home, НЕ SmartAir2;
- Wi-Fi модуль — **MK-QTWIFI-04** (или 03), hostname вида
  `uplus-haier-ac-XXXXXX-v0`, тип устройства `UHOME_OVERSEAS_AC`;
- с компьютера порт отвечает:

  ```bash
  nc -zv <IP-кондиционера> 56800
  # → succeeded / open
  ```

Если порт закрыт — см. [раздел про сеть](#сеть-vlanfirewall).
Если приложение другое — сверьтесь с таблицей в [README](README.md).

## 2. Как это устроено

```
[Приложение Haier]──облако uws-gea-euro.haieriot.net──┐
                                                      │ (однократно: достаём local key)
[Home Assistant]────TCP 56800, шифрованный uSS/HRDP───┴──>[Кондиционер]
```

- Кондиционер слушает **локальный** протокол uSS/HRDP на TCP **56800**.
  Трафик зашифрован AES-ключом (`localKey`), который выдаёт облако.
- Скрипты этого репозитория один раз авторизуются в европейском облаке
  вашей учёткой и забирают `device ID` + `local key`.
- Дальше интеграция [`enapt/haismart-local`](https://github.com/enapt/haismart-local)
  общается с кондиционером напрямую по LAN. Облако больше не нужно.

## 3. Пошаговое подключение

### Шаг 1. Достаём ключ из облака

Полная инструкция — в [README](README.md), кратко:

```bash
pip install httpx cryptography paho-mqtt

# APP_ID/APP_KEY вытаскиваются jadx'ом из APK приложения (см. README, шаг 1)
export HAISMART_APP_ID=MB-XXXXXXXX-0001
export HAISMART_APP_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

python3 haier_euro_keys.py --username you@example.com
```

Получите:

```
Кондиционер
  device ID (MAC)  XXXXXXXXXXXX
  local key        xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
  key version      1377
```

> Есть альтернативный путь — локальный MQTT-шлюз (`gw-gea-euro.haieriot.net:56789`),
> он тоже реализован в скрипте.

### Шаг 2. Ставим интеграцию и добавляем кондиционер

1. Установите [`enapt/haismart-local`](https://github.com/enapt/haismart-local)
   через HACS или копированием в `custom_components/haismart`.
2. Перезапустите Home Assistant.
3. **Настройки → Устройства и службы → Добавить интеграцию → Haismart** →
   **«У меня уже есть этот блок и его локальный ключ»**.
4. Введите IP кондиционера и вставьте `local key` из шага 1.

### Шаг 3. Автообновление ключа (обязательно!)

Кондиционер **ротирует localKey несколько раз в день**, после чего HA показывает
«недоступен». Решения (любое из двух):

- крон на `haier_key_refresh.py` каждые 30 минут — сам подтягивает свежий ключ
  в конфиг HA и перезапускает его (см. README, шаг 4);
- **заблокировать кондиционеру выход в интернет** на роутере — у офлайн-юнита
  ключ перестаёт меняться, и сохранённый ключ живёт вечно.

## 4. Что работает сразу

После подключения вы получаете:

| Сущность | Возможности |
|---|---|
| `climate.*` | вкл/выкл, режимы (cool/heat/dry/fan/auto), температура, скорость вентилятора, качели вертикальные/горизонтальные |
| датчики | комнатная температура и прочая телеметрия |
| переключатель | **Здоровье** (ионизация) |
| кнопка | **Самоочистка** |

Управление идёт локально, опрос раз в ~30 с, задержка команды < 1 c.

## 5. Турбо, Тихо, Подсветка и Комфортный поток — чего нет "из коробки"

Это главная находка проекта. У compact-12 эти функции есть **на пульте**, но их
не было ни в приложении, ни в интеграции. Мы нашли, где они лежат в протоколе,
и добавили:

| Переключатель | Что делает |
|---|---|
| **Турбо** | форсированный обдув |
| **Тихо** | минимально шумный режим |
| **Экран** | индикатор температуры на блоке (логика инвертирована!) |
| **Комфортный поток вверх / вниз** | отклонение потока от людей; взаимоисключающие |

Плюс набор read-only индикаторов (сон, блокировка, увлажнение, датчик присутствия,
энергосбережение и т.п.).

Подробное техописание (адреса битов, ограничения, что пишется групповой командой) —
в отдельном документе **[COMPACT12-CONTROLS.md](COMPACT12-CONTROLS.md)**.

### Как установить модификации

Файлы из каталога `custom_components/haismart/` этого репозитория кладутся
поверх установленных файлов интеграции `enapt/haismart-local`
(заменяемые файлы перечислены в [COMPACT12-CONTROLS.md](COMPACT12-CONTROLS.md)),
после чего HA перезапускается. Переключатели появятся как обычные
`switch.*` сущности — можно добавить на панель или в автоматизации.

## 6. Как мы это нашли (методология)

Если захотите добавить что-то ещё на своей модели:

1. **Сравнение статусов.** Каждое нажатие кнопки на пульте меняет поля
   в статусном отчёте юнита. Логируем дампы до/после и сравниваем.
2. **Запись группой.** Изменённые биты записываются обратно командой
   group-set (для compact-12 — слово 10 массива из 12 слов).
3. **Проверка отказа.** Если юнит не поддерживает функцию, он отвечает
   `reply_refused` («кондиционер отказал в команде») — например,
   электрообогрев и «свежий воздух» на холодильнике отклоняются железом.

Инструмент для шага 1 — `tools/status_watch.py` этого репозитория:
опрашивает юнит раз в 2 секунды и печатает diff декодированных полей.

## 7. Решение проблем

<details>
<summary><b>nc -z на порт 56800 не проходит</b></summary>

Почти всегда — изоляция сети/VLAN (IoT-сегмент). Добавьте на роутере правило,
разрешающее HA→кондиционер по TCP 56800 (у нас MikroTik: forward-правило между
bridge-IoT и bridge-LAN).
</details>

<details>
<summary><b>Через несколько часов/дней кондиционер стал «недоступен»</b></summary>

Классика: облако ротировало ключ. Настройте cron с `haier_key_refresh.py`
или заблокируйте юниту интернет (см. шаг 3).
</details>

<details>
<summary><b>В логах «the air conditioner refused the command» / reply_refused</b></summary>

Юнит отклонил команду — такой функции у модели физически нет (например,
электрообогрев у холодильника) либо она недоступна в текущем режиме.
Это не баг: уберите неиспользуемые сущности с панели.
</details>

<details>
<summary><b>Команды срабатывают через раз</b></summary>

Кондиционер держит **одну локальную сессию одновременно** (~17 сек кап).
Не запускайте две локальные Haier-интеграции на один юнит; убедитесь,
что ничего больше не опрашивает порт 56800.
</details>

<details>
<summary><b>В приложении меньше кнопок, чем на пульте</b></summary>

Нормально: часть функций (Турбо, Тихо, Комфортный поток, подсветка) в нашем
приложении недоступна, но пишется в юнит по Wi-Fi — мы добавили их в HA сами
(см. раздел 5).
</details>

<details>
<summary><b>HA и кондиционер в разных сетях — ключ получил, интеграция не видит юнит</b></summary>

Тот же вопрос сети: интеграции нужен прямой доступ к IP:56800. Проверьте
`nc -z` **именно с хоста HA** (для docker — из контейнера).
</details>

## 8. Ограничения и совместимость

- Всё подтверждено **только на AAC1UKZ01** (compact-12, только холод).
  Другие модели семейства скорее всего похожи, но адреса функций могут
  отличаться — сверяйтесь по методологии раздела 6 и не пишите вслепую.
- Семейства *classic* и *extended* поддержаны апстримом `haismart-local`.
- Кривая сна (`sleep_curve`) у compact-12 **не пишется** локально — только
  с пульта.
- Электрообогрев и «свежий воздух» отклоняются железом холодильных моделей —
  соответствующие сущности из интеграции для них удалены.
